# Формальна специфікація SIPL (версія мови 1.0)

Машинозчитувана граматика: [`grammar/sipl.lark`](../grammar/sipl.lark).
Еталонний парсер: [`src/sipl/parser.py`](../src/sipl/parser.py). Тест
`tests/test_grammar.py` перевіряє, що граматика і парсер приймають та
відхиляють одні й ті самі програми.

## БНФ курсу

```
<програма> ::= begin <оператор> end
<оператор> ::= <змінна> := <вираз>
             | <оператор> ; <оператор>
             | if <умова> then <оператор> else <оператор>
             | while <умова> do <оператор>
             | begin <оператор> end
             | skip
<вираз>    ::= <число> | <змінна>
             | <вираз> + <вираз> | <вираз> - <вираз> | <вираз> * <вираз>
             | ( <вираз> )
<умова>    ::= <вираз> = <вираз> | <вираз> > <вираз>
             | <умова> ∨ <умова> | ¬ <умова> | ( <умова> )
<змінна>   ::= ідентифікатор
<число>    ::= ... | -1 | 0 | 1 | ...
```

Дерево синтаксичного виводу (`sipl tree`) будується саме в цих
нетерміналах і правилах.

## Зняття неоднозначності

БНФ курсу неоднозначна, тому зафіксовано пріоритети (від сильнішого):

| Рівень | Конструкції | Асоціативність |
|---|---|---|
| 1 | `*` | ліва |
| 2 | `+`, `-` | ліва |
| 3 | `=`, `>` | не асоціативні |
| 4 | `not` (`¬`) | префіксна |
| 5 | `or` (`∨`) | ліва |
| 6 | `;` | ліва, найслабша |

Наслідок останнього рядка: тіло `while` та гілки `if` - це **один**
оператор. `while b do S1; S2` означає `(while b do S1); S2`; для кількох
операторів у тілі потрібен `begin ... end`. Гілка `else` обов'язкова.

`;` - роздільник, а не термінатор: `begin X := 1; end` є помилкою (`E004`).

## Лексика

| Лексема | Вигляд |
|---|---|
| Ключові слова | `begin end if then else while do skip or not` |
| Зарезервовані | `and true false` (зайняті мовою тверджень) |
| Змінна | `[A-Za-z_][A-Za-z0-9_]*`, регістр має значення |
| Число | `[0-9]+`; від'ємний літерал - `-` перед числом у позиції операнда (`X := -1`, `X - -1`) |
| Оператори | `:=  ;  +  -  *  (  )  =  >` |
| Юнікод-синоніми | `∨` = `or`, `¬` = `not`, `×` та `·` = `*` |
| Коментар | від `//` до кінця рядка |
| Анотація | коментар виду `//@ ключ: текст` (див. [proof-assistant.md](proof-assistant.md)) |

Пробіли, табуляції та переходи рядка лише розділяють лексеми.

## Розширення: мова тверджень

Перед-/післяумови та інваріанти записуються надмножиною мови умов:
додатково `and` (`∧`), `->` (`→`), `<`, `>=` (`≥`), `<=` (`≤`), `!=` (`≠`),
`true`, `false` та степінь `^` (правоасоціативний, сильніший за `*`).
У **програмах** ці конструкції заборонені - парсер повідомляє `E003` і
підказує, як виразити їх засобами базової SIPL.

## Коди діагностики

| Код | Значення |
|---|---|
| `E001` | лексична помилка (неочікуваний символ, `2y`) |
| `E002` | синтаксична помилка: очікувалось одне, знайдено інше |
| `E003` | конструкція поза базовою SIPL (`<`, `and`, `^` ...) |
| `E004` | зайва `;` перед `end` |
| `P001`-`P006` | помилки специфікації для `sipl prove` |
| `R001`, `R002` | значення терму не визначене: немає змінної у стані / вичерпано ліміт кроків |
| `U001` | помилка використання CLI |

Кожна діагностика має `SourceSpan` (рядок, колонка, зсуви початку й кінця).
