# Асистент доведення коректності циклічних програм (SEM-04)

Реалізація: [`src/sipl/proof/`](../src/sipl/proof).

## Специфікація

Записується анотаціями-коментарями або параметрами командного рядка.

```
//@ pre: Y >= 0 and X = A and Y = B     // передумова
//@ post: R = A^B                       // післяумова
begin
  R := 1;
  //@ inv: R * X^Y = A^B and Y >= 0     // інваріант найближчого наступного while
  //@ variant: Y                        // варіант (для повної коректності)
  while Y > 0 do
  begin R := R * X; Y := Y - 1 end
end
```

* Кілька `pre` / `post` / `inv` об'єднуються кон'юнкцією.
* Змінні, яких програма не змінює (`A`, `B`), фіксують початкові значення.
* `--pre`, `--post`, `--inv` (по одному на цикл, у порядку запису),
  `--variant` замінюють анотації - зручно пробувати різні інваріанти.
* Мова тверджень описана в [grammar.md](grammar.md#розширення-мова-тверджень).

## Що саме доводиться

Індуктивне твердження - інваріант `I`; індукція ведеться за кількістю
ітерацій циклу `while b do S`:

| Умова | Формула | Зміст |
|---|---|---|
| база (`entry`) | `P → wp(S0, I)` | інваріант істинний перед першою ітерацією |
| крок (`preserve`) | `I ∧ b → wp(S, I)` | ітерація зберігає інваріант |
| вихід (`exit`) | `I ∧ ¬b → wp(S1, Q)` | після циклу отримуємо потрібне |
| `variant_bound` | `I ∧ b → V ≥ 0` | варіант обмежений знизу |
| `variant_decrease` | `I ∧ b ∧ V = v0 → wp(S, V < v0)` | ітерація зменшує варіант |

`wp` - найслабша передумова: `wp(x := e, Q) = Q[e/x]`,
`wp(S1; S2, Q) = wp(S1, wp(S2, Q))`,
`wp(if b then S1 else S2, Q) = (b → wp(S1, Q)) ∧ (¬b → wp(S2, Q))`,
`wp(while, Q) = I`.

Перші три умови дають **часткову** коректність `{P} програма {Q}`; з двома
останніми для кожного циклу - **повну** (програма ще й завершується).

Правило рамки: кон'юнкти післяумови циклу, які не згадують змінених у циклі
змінних, переносяться через цикл без участі інваріанта (тому інваріант
внутрішнього циклу не мусить повторювати факти про зовнішній).

## Як перевіряється кожна умова

1. **Символьний доказ** ([`prover.py`](../src/sipl/proof/prover.py)),
   спростуванням заперечення:
   * гіпотези `x = вираз` застосовуються як підстановки;
   * порівняння зводяться до поліноміальних атомів `p = 0` та `p ≥ 1`,
     формула - до ДНФ (розбір випадків);
   * у кожному випадку шукається суперечність: підстановка лінійних
     рівностей, виведення `q = 1` з `q ≥ 1` та `2 - q ≥ 1`, невід'ємна
     цілочисельна комбінація нерівностей (та їх попарних добутків) зі сталим
     результатом;
   * для степеня зі змінним показником додаються властивості
     `e = 0 → b^e = 1` та `e ≥ 0 → b^(e+k) = b^e · b^k`.

   Усі кроки записуються в протокол (proof trace) і їх можна перевірити вручну.
2. Якщо доказу немає - **пошук контрприкладу**: повний перебір малих цілих
   значень змінних формули плюс випадкові проби на ширших діапазонах.
3. **Динамічна перевірка**: програма виконується (через семантичний терм)
   на всіх малих початкових станах, що задовольняють передумову; на кожній
   ітерації контролюються інваріант і варіант, наприкінці - післяумова.

## Статуси та висновки

| Статус умови | Зміст |
|---|---|
| `proved` | є символьний доказ |
| `refuted` | знайдено стан, де гіпотези істинні, а ціль хибна |
| `tested` | доказу немає, контрприкладу серед перевірених станів теж - **це не доведення** |

| Висновок | Коли | Код завершення |
|---|---|---|
| `proved` | усі умови доведено | 0 |
| `tested` | контрприкладів немає, але частину умов треба довести вручну | 0 |
| `failed` | інваріант/варіант не проходить: він або хибний на реальному виконанні, або не індуктивний (надто слабкий) | 1 |
| `refuted` | знайдено вхід із передумовою, на якому порушується післяумова - хибна сама програма або специфікація | 1 |

Розрізнення двох причин `failed` - головна користь динамічної перевірки:
контрприклад до умови "крок" може бути недосяжним станом, і тоді інваріант
треба підсилити, а не відкидати.

## Межі автоматизації

* Асистент **перевіряє** запропонований інваріант, але не вигадує його.
* Символьний метод коректний, але неповний: відмова не означає, що формула
  хибна. Він розрахований на поліноміальну арифметику з невеликою кількістю
  гіпотез; складні нелінійні факти (напр. `X^4 - X^2 + 1 > 0`) лишаються
  у статусі `tested`.
* Відсутність контрприкладу на малих значеннях - свідчення, а не доказ.
* Валідність довільних формул цілочисельної арифметики з множенням
  нерозв'язна, тож універсального вирішувача тут бути не може.
* Твердження зі степенем `b^e` вважаються визначеними лише для `e ≥ 0`;
  стани з від'ємним показником під час перебору пропускаються.
